# Known limitations and accepted risks

Every known limitation and accepted risk of 6529 Works v1, one row per risk, for auditors: what
it is, what follows, what mitigates it, and where it is recorded. Rows cite spec rule IDs and the
finding IDs of the [internal adversarial review](../security/internal-review-2026-10.md). No
external audit has happened yet.

> Pre-audit. See the [project status](../../README.md#status).

## How to read this page

| Type | Meaning |
| --- | --- |
| **Accepted** | A risk recorded as accepted or residual by an ADR, an owner decision, the internal review or a module's design (formerly recorded in its README). Changing it needs a design decision. |
| **Gap** | Not implemented, or a v1 limitation. It may be fixed later without reopening a decision. |
| **Closed** | Resolved by a later change; the row records how, and what remains. |
| **Removed** | Left with the code it described; the ID is not reused. Rows removed before the second permanence pass are on the `v1.0.0-rc.1` page; rows that pass removed keep a one-line entry here. |

Delays use the [delay classes](../glossary.md#delay-class): at once (NETWORK and the operational
keys); 24 hours (PARAMETER_SETTER); 3 days (FUNDS_SETTER); 7 days (SUCCESSOR_SETTER and ADMIN).
The brake, when one is set, can delay a scheduled action once by 7 days. Roles and their
selectors are on [Roles](roles.md).

A replaced module stays the seed source of the works minted under it ([ENT-18][ent]), so it must stay readable; only its subscription can be retired. | Off anvil the deploy requires `VRF_COORDINATOR` unless `NO_VRF=1` declines it explicitly; the [replacement procedure](../../script/README.md#replacing-one-of-streams-dependencies) covers the rest. | [script README, step 7][script-vrf] |
| LIM-ENT-5 | Accepted | **On mainnet the network Safe owns the VRF subscription** (DEPS-4, `DeployGuards`). The subscription owner can cancel it or remove the module at once, outside the governed delays. | If the subscription is cancelled, curated VRF works cannot start until a new subscription is funded and `setConfig` (24 hours) points the module at it. | Keep the balance small; current practice is to watch the coordinator's `SubscriptionCanceled`, `SubscriptionConsumerRemoved` and `SubscriptionOwnerTransferRequested` events. | [script README, step 7][script-vrf] |
| LIM-ENT-6 | Accepted | **`entropyModuleOf` is linear in the module's eras.** Each entropy-module replacement adds an era that `Stream.entropyModuleOf` scans, one storage read each ([ENT-18][ent]). `WorkRecords.openRecord` reads it once for a VRF work, and the renderer reads it, with a 300,000-gas cap, for a VRF work whose record is not open yet. | Around 130 eras the renderer's capped read would fail, and `tokenURI` of a VRF work whose record is not open would revert (`RendererReadFailed`) until the record opens. | Each replacement is a 7-day network action (owner decision 16), so 130 eras are far beyond any planned use. | rc.2 review |
| LIM-ENT-7 | Accepted | **A module or coordinator replacement can redraw a seed** ([ENT-8, ENT-18][ent]). Replacing the entropy module, which every package-registry replacement requires, discards the seeds the old module delivered for content not yet minted, so that content gets a second draw from the new module, and leaves its pending requests to a module Stream no longer reads, so that content is drawn anew; a coordinator swap orphans every pending request, including one whose delivery is already visible. | Content not yet minted can end up with another seed than the one first delivered or seen in flight. Minted works keep their seeds (ENT-18). | Today's module reads no predecessor. The runbook lists the unminted content with a seed delivered or pending before a module replacement, so the network can schedule it when there is none or publish the redraw; its current practice is to swap coordinators only with no request pending ([replacement procedure](../../script/README.md#replacing-one-of-streams-dependencies), [step 7][script-vrf]). | [Entropy: coordinator change](../spec/entropy.md#coordinator-change) |
| LIM-ENT-8 | Accepted | **Federated VRF is requester-paid and off at launch** ([ENT-20 to ENT-22][ent]). `requestFederatedSeed` forwards the whole payment to Chainlink's VRF v2.5 wrapper at the wrapper's own quote; the wrapper address is zero at launch, so no federated VRF request is possible until the network sets one (`setWrapper`, 7 days). | An overpayment goes to the provider with the request and is not refunded. A federated VRF work mints only after its seed is delivered. | Read the wrapper's quote before requesting. | `FederationSecondPass.t.sol` |
| LIM-ENT-9 | Accepted | **A contract on a revoked template can still buy a federated seed** ([ENT-20][ent]). `requestFederatedSeed` checks the contract's listing, not its template's status, so the artist can pay for a seed its contract cannot use while the template stays revoked. | The requester's payment is spent; nothing of the network's is used. | None needed: the requester pays and chooses to ask. | ADR 0009 (review fixes) |
